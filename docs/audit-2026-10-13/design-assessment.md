## 设计专属性判断（先于任何自动检测）

这不是一套没有产品性格的通用财务后台。柔和纸色、抹茶绿金额板、Cheese 云朵、轻圆角、紧凑数字键盘和细小的生活化图标共同支持“顺手记下生活里的小开销”，而不是投资仪表盘或企业报销。390×844 与 320×568 的主流程都体现出真实的移动 WebView 使用场景。

但专属性主要集中在“皮肤与情绪”，尚未完整转化为“业务含义”。同一个可爱角色承担陪伴、互动玩具、保存入口三种职责；收据入口、个人形象、地点、账本状态都被压成小符号或浅色小字。新用户记住了云朵，却未必知道账目什么时候保存、存在哪里、哪一步还没完成。

最值得保留的是轻松且不带财务羞耻感的语气。最值得补齐的是一套同样温暖、但能够解释“来源 → 核对 → 保存 → 同步/分享”的明确交互语言。新资产应帮助解释这些状态，而不是给每张卡片再加一朵云。

## 总体判断

基础相当完整：本地录入快、主导航只有两个目标、账目能编辑/复制/撤销、设置有清晰分区，视觉风格也高度一致。主要差距不是缺少装饰，而是关键动作与关键承诺被过度弱化：保存入口、草稿保护、键盘焦点、存储边界。

**设计健康分：25/40（62.5%，Acceptable / 可用但仍有显著改进空间）。** 这不是完整 WCAG 合规审计，也不是生产账户可用性验收。

## 做得好的三点

1. **移动端快速路径是有设计的。** 数字键盘、金额展示和固定双标签导航形成稳定肌肉记忆；320×568 仍保留完整数字键盘、用途和附加动作，不靠挤成不可点击的桌面缩略图。主要操作仅需输入金额、选用途、确认。证据：截图 01、02、09；`App.jsx:754–757`、`pocket-layout.css:80–127,254–277`。
2. **复杂能力多数采用逐步展开。** 生活回顾默认折叠；设置按账本/工具/偏好分组；AI 候选列表默认只展开首项；圈子邀请、移除和退出都在确认前提供上下文。证据：`SettingsPage.jsx:10–20`、`AiSummary.jsx:85–112`、`AiImportPage.jsx:301,443–478`、`AccountViews.jsx:102–106`。后两类登录后流程是源码观察，非实测。
3. **生活感没有牺牲所有数据谨慎。** 地点弹窗明确说明坐标交给地图服务、保存后账本成员可见、可移除关闭；账目删除有撤销；AI 对可能重复的记录标记复核而不直接擅自丢弃。证据：截图 10；`LocationViews.jsx:8–17`、`App.jsx:643–653`、`AiImportPage.jsx:284–300`。

## 优先问题

### A1 — [P1] 主任务的“完成”动作直到最后才出现，且只有一个附着在角色旁的勾号

**观察与位置：** 初次记录首屏没有“保存/记下这笔”按钮，也没有“先输入金额，再选择用途”的可见提示；输入 1 并选择 Dining 后，金额卡右下角才出现勾号。`App.jsx:743–754` 已计算 `enterAmount/selectCategory` 标签，却把它传给只有有效时才渲染的按钮；实际条件在 `PocketMascot.jsx:232`。截图 01 与 02 直接展示差异。

**影响：** Jordan 不知道选用途是必需条件，也可能把勾号理解为角色状态而不是入账操作。390×844 中确认位于上部金额卡，Casey 完成下半屏键盘输入后必须重新上移拇指；底部的 Add 是导航，不是提交。这是产品核心路径的发现性问题，不是云朵美术质量问题。

**建议：** 保留 Cheese 的反馈与庆祝，但让记录页始终有明确、稳定的“记下这笔”动作。无效时显示简短原因“输入金额 / 选择用途”；有效时可显示“记下 ¥…”。若必须保留云朵旁确认，至少加入可见文字且不要使角色本身成为保存的唯一线索；移动端优先稳定在键盘下方的拇指区域。

**验收：** 首次用户不经帮助，在 5 秒内指出“最终在哪里保存、还缺什么”；金额/类别无效与有效两个状态位置不跳；原有键盘快捷键保留。建议命令：`$impeccable onboard`、`$impeccable clarify`。

### A2 — [P1] 快速整理会在普通导航中无提示丢失草稿

**实测复现：** 在快速整理文本框输入合成文本 `AUDIT DRAFT — coffee 18, not a real purchase` → 点击 Ledger → 通过账本的 Quick entry 返回 → 文本变为空，没有确认提示。A 从 AX 状态与 textarea 的实际 `value` 读取确认空串，未提交 AI 请求。

**源码：** `AiImportPage.jsx:161–173` 将 text/files/items 保存在组件本地状态；`App.jsx:301–304` 直接切换 view，`App.jsx:770` 条件挂载 AiImportPage；没有内部导航保存草稿或离开提醒。`AiImportPage.jsx:198–210` 处理卸载/账本作用域变化，但不是草稿持久化。已分析候选同样保存在本地 state，因此候选离页丢失属于源码推断，未在登录状态实测。

**影响：** 用户查一眼账本是否已经有这笔，或按“登录”去解锁功能，就可能丢掉刚整理的长文本及附件选择。AI 批量导入是高投入任务，这种损失比一次轻触误操作更严重。

**建议：** 以用户/账本为边界保存临时整理会话，至少跨内部导航保留文本与候选；敏感附件不应无解释地长期落盘。不能恢复的内容应在离开前明确提示，提供“继续整理 / 放弃”两个选项。登录返回原页面时保留同一来源，而不是重置流程。

**验收：** 输入→账本→返回、输入→账户→返回均保留来源；切换到不同账本不会误带入旧账本的候选；用户主动清空是唯一无提示清空路径。建议命令：`$impeccable harden`。

### A3 — [P1] “安静”视觉策略同时压低了文字可读性和键盘焦点

**实测与源码：** `--muted:#879077` 在 `--paper:#f8f7f1` 上计算对比度约 **3.11:1**；AI 主要说明实测为该颜色、13px，文件限制为 10px。账目时间 `#a0a68f` 对纸色约 **2.34:1**；统计小字 `#909b7d` 对绿色卡片约 **2.40:1**。基线：`styles.css:1,84,98`、`account-styles.css:27,71,78`。不是所有正文都失败——深色主文本对纸色约 10.94:1。

`pocket-layout.css:33–34` 对 label、input、select、textarea 的焦点轮廓与阴影使用全局 `none!important`；`account-styles.css:48,101` 还移除输入与头像入口的焦点提示。截图 04 中通过 Tab 进入金额字段后仅有文字选择，没有清晰字段焦点边界。原生选择控件没有文本选择这一补充线索，影响更明显。`refinements.css:123–129` 恢复了键盘/类别/导航等按钮的 ring，却未覆盖表单。

**影响：** Sam 在金额、币种、类别、付款人、备注之间移动时难以定位；低视力或户外手机用户读不清时间、存储位置和帮助说明。最容易被看漏的恰好是风险说明，而不是装饰。

**建议：** 把“可读的次级信息”和“非信息性装饰”拆成两个颜色 token；普通说明采用至少 4.5:1 的正文目标，低对比只用于装饰。恢复所有表单与头像入口的 `:focus-visible`/`:focus-within` ring；不要依赖 caret、文字选中或背景微差作为唯一焦点信号。优先将关键辅助文案从 8–10px 提升到可读层级，不要求整体变黑变重。

**验收：** 键盘从顶部到保存能持续看见当前位置；纸色、卡片色及四种主题中的关键说明均单独核算；200% 放大与移动端仍可完成编辑。建议命令：`$impeccable audit`、`$impeccable typeset`。

### A4 — [P2] 保存发生在哪里、是否已确认，没有在入账那一刻讲清楚

**观察：** 记录页显示 Saved 与今日累计变化，却没有“仅保存在此浏览器”；同一说明进入账本/设置后才出现，而且是非常小的页脚。截图 01/02 与 03/05 对照可见。`App.jsx:744` 定义存储状态，`App.jsx:772` 只在非 record 页渲染；`pocket-layout.css:24` 还隐藏了 entry-actions 中的存储状态。

**源码风险：** `App.jsx:571–572` 先庆祝并发送 savedShort，再启动异步写入；`App.jsx:522–542` 已有待确认 outbox 与失败重试，这是很好的可靠性基础，但界面没有向用户区分“本地已收下”和“服务端已确认”。此处是远程路径的源码判断，未模拟线上失败；不声称实测发生丢账。

**影响：** 访客可能把“个人账本”当作跨设备账户，把 Saved 当成云端确认。必须去另一个页面才知道存储范围，增加信任落差。

**建议：** 在记录页提供低干扰但可读的持久状态“本机保存 / 已同步 / 待同步”；成功反馈与真实状态对应。首次访客保存后可一次性说明“这份账本目前仅在此浏览器”，并提供可用的同步或备份路径；无需每次弹窗。

**验收：** 用户不离开记录页即可判断存储位置；待确认、成功、失败不会用同一句承诺；重试成功后状态自动回到稳定态。建议命令：`$impeccable clarify`、`$impeccable harden`。

### A5 — [P2] 功能不可用时仍展示完整可编辑工作区，禁用动作又看起来可执行

**观察：** 沙箱快速整理页同时显示“Sign in to use entry analysis”、可输入文本、Choose files 和深色 Organize。AX 明确标记 Organize disabled，但肉眼与正常主按钮相近（截图 08）。圈子/回顾的登录按钮通向账户页，而当前沙箱账户页只有 Google 未启用等文案（截图 06、07）。后者是环境事实，不代表生产也不可用。

**源码：** `AiImportPage.jsx:407–416` 的权限门只加提示、不阻止来源工作区；文本/文件仅在 working/busy 禁用，`AiImportPage.jsx:434` 才阻止分析。`styles.css:10` 把所有 disabled button 的透明度设为 1。`AccountViews.jsx:70–71,91` 与 `AiSummary.jsx:90–91` 分别独立判定可用性，形成不同的不可用表达。

**影响：** 用户在明确无法完成的状态先投入文本/附件工作，再寻找权限；当前沙箱出现登录死路。结合 A2，前往账户还会丢掉输入。即使线上账户启用，这种“先准备、再得知不能处理”的顺序仍需有清晰承诺。

**建议：** 统一访客、已登录未配置、正在处理三种状态。可选择先登录再进入来源区，或明确支持“先草拟，登录后继续”；后者必须保留草稿。禁用按钮使用可辨状态与就近原因，不能仅在程序层 disabled。账户没有可用登录方式时，不应继续提供一个看似能完成登录的主行动。

**验收：** 每种 config/isRemote 组合都能解释能做什么、不能做什么、下一步是否可完成；已登录未开 AI 不出现误导性操作；权限入口往返不丢内容。建议命令：`$impeccable clarify`、`$impeccable onboard`。

| 工作记忆 | 未通过 | 为确认是否重复而暂离快速整理，会清空当前文本；需要用户在屏幕外记忆/重新粘贴。 |
| 渐进披露 | 通过 | 生活回顾、AI候选、类别编辑补充控件及圈子管理大多按需展开。 |

**合计 4/8 未通过：按本 playbook 是高负荷，主要集中在二级整理和个性化流程；不应误读为主数字键盘本身复杂。** 数字键盘的10个数字属于输入编码，不把它当作10个业务决策处罚。类别条手机同时完整可见约3项，不把隐藏的6个类别全部计作同时可见选项。

超过4项的明确决策点：桌面个人形象11个头像+上传、8色；货币弹出菜单13种币种；AI记录种类6项；AI展开候选9个常规字段再加分摊。优先减少需要理解的决策，不是机械删掉合理的货币或头像。

## 情绪旅程

- **入口：** 没有强制注册，低压力的颜色和笑脸让“记一笔”像照顾生活，而非接受财务评价。入口情绪是好的。
- **输入：** 大数字与响应式键盘提供控制感。第一处低谷是“输入完了，怎么交？”——保存动作的突然出现需要用户自己悟到。
- **完成：** 云朵庆祝与 Saved 是清晰峰值，但峰值需要建立在可信保存状态上；不能让正向情绪代替同步事实。
- **扩展能力：** 圈子/回顾/AI 入口承诺了更多价值；访客进入权限门时没有具体收益预览，又可能遇到账户配置空态。这里应有明确、短小的路径，而不是只用 Sign in to sync 反复转场。
- **中断后重返：** AI文本被清空形成负面终点。峰终体验最需要优先修的不是庆祝动画，而是“回来以后我的东西还在”。

## Persona 风险

### Jordan — 第一次使用

路径：进入记录 → 点金额键 → 看用途 → 寻找完成动作。

- 初屏没有可见保存按钮；底部 Add 更像“添加”动作，但实际只是当前 tab。
- 顶部头像实际打开设置；收据图标实际进入快速整理，只有辅助技术标签或悬浮 title 告知用途。
- 圈子入口只说需要登录，缺少“共同看什么、哪些成员可以改什么”的最短说明。已登录邀请页有 sharedHint 是积极基础，但访客看不到。
- 账户配置不可用时没有真正能推进的下一步。此条限于沙箱，不据此指控生产配置。

### Casey — 单手、短时间、经常被打断

路径：下半屏拇指键盘录入 → 选择用途 → 确认 → 切换应用后回来。

- 390×844 的保存动作在金额卡内、键盘上方，熟练后仍要上下移手；底部主区留给导航。
- 日期按钮移动端高28px、编辑用途高22px、设置头像36×36、用途pill42px（`pocket-layout.css:87,96,117,259`）。它们可用，但没有统一达到44px触控目标；重要日期/编辑尤其紧。
- 主手工草稿在 App state 中可跨内部页保留，是优点；AI草稿却离页丢失，行为不一致。
- 320×568 适配没有明显溢出，是值得保留的成果，不能为了添加图而破坏。

### Sam — 键盘与低视力

路径：Tab 到账本筛选 → 展开账目操作 → 编辑金额/币种/用途 → 保存。

- 输入、选择控件全局取消焦点ring；对话框本身的原生focus/escape很好，但不能抵消字段层可见焦点缺失。
- 账目时间、存储范围、帮助文案过浅过小；单纯放大字号不能修复所有对比问题。
- 屏幕阅读器侧，图标动作大多已有 aria-label，主类别已有 pressed，模态有标题，这是明确优点；本轮只验证AX结构，未冒充真实NVDA/VoiceOver完成测试。
- 圈子接收动画在 `CircleReactions.jsx:92,231–233` 是 aria-hidden 视觉效果，本轮未看到对应可读收件历史/播报；若该互动承载协作信息，需另补等效反馈。此条为源码观察，不是实测断言。

## 次要观察

- **[P3] 快速整理旁出现孤立的“0”。** 截图08中 Organize 右侧的0来自 `AiImportPage.jsx:435` 的 `(text || files.length || items.length) && ...` 在空状态返回数字0；应把条件转为布尔值。此项是视觉杂讯，不是计数功能。
- **[P2] 返回不按实际入口回退。** `App.jsx:753` 将非设置的二级页 Back 都导向设置；从记录/账本的快捷入口进入快速整理后，Back 并不返回来处。保持双tab可退出，所以不是被困住，但会增加位置理解成本。
- **[P2] 桌面空间分配不均。** `styles.css:18–21` 的左右grid加上 `pocket-layout.css:188–206` 的单行横向类别，导致宽屏右侧大量空闲但仍裁切类别；底部导航遮挡一部分首屏键盘，需要滚动。移动端可保留横向条，桌面可利用闲置区显示全部常用类别。
- **[P3] 辅助文字与界面语言有局部差异。** 英文界面下本地默认名仍为“我”，不影响金额，但账户/圈子场景的默认身份含义可以随语言表达。没有把它认定为用户自定义名字错误。
- AI候选的“需要复核”标签、重复判断、时间/类别缺失标记有价值；建议先处理必须复核的候选，再展开其他非关键字段，不需要把每条候选变成长表单。
- 不建议用更大插画填满账户未配置页或桌面空白；先让状态与操作关系成立，再添加适量业务场景图。

## 新资产的业务适配方向（不是界面修复）

1. **本地与同步：** 同一账本在设备/小云之间的轻量状态插画，适合首次保存、离线和账户页；不要把“仅本地”画成错误，也不要用完成勾号暗示未确认的远程同步。
2. **整理与复核：** 收据/纸条变成几条可编辑账目，其中一处标记待核对。插画表达“辅助整理”而不是“AI绝不出错”。语言内容保留在HTML，图片不嵌中英文字。
3. **共同记账：** 两到三位生活化角色围绕同一册账本，适用于圈子初次使用/邀请。应表达共同查看与记录，而不是银行、支付或结算承诺。
4. **足迹与生活回顾：** 地点标记配记账小纸条、月度小回顾等轻量资产，可增强产品专属性；必须服务空态/说明，不能干扰金额与键盘。

Cheese 可作为所有资产的联结角色，但不替代按钮文字、权限说明、可读性或草稿恢复。P1问题不能靠新图片消除。

## 结论与尚需决策的问题

保留现有奶油白/抹茶绿/Cheese 的世界观。首轮应先稳定“看得到怎么完成、离开不丢、看得清状态”，再把业务场景资产接入空态与帮助位置。没有发现需要因为视觉风格而整体推倒重做的证据。

最终综合报告应向用户确认以下三项，不在本子评估中代替用户选择：

1. 当前优先级是哪一类：**可读性与草稿保护（推荐） / 首次记账完成路径 / AI整理与账户衔接**？
2. 保存动作如何保留角色个性：**文字保存按钮+Cheese反馈（推荐） / 云朵旁保留勾号并加文字 / 先保持现状，只补最短引导**？
3. 访客账本的长期定位是什么：**可长期使用的本地账本并提供备份 / 免登录试用后引导同步 / 主要服务Telegram已登录用户**？这会直接决定存储说明、账户空态和新资产摆放的位置。
