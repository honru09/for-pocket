# for-pocket 视觉与交互契约

这份文档把已经采用的样式写成可执行约束。后续补素材时，先放入真实页面验证，不要只交付漂亮的素材展示板。用户最新要求是组件、插图、字体及交互彼此协调，首页仍以快速记账为中心。

## 一套层级

| 角色 | 大小 / 字重 | 使用位置 |
| --- | --- | --- |
| 页面标题 | 24px / 750 | 设置、个人资料等独立页 |
| 抽屉标题 | 20px / 700 | 共享 Sheet，保留关闭按钮的 44px 命中区 |
| 分区标题 | 16px / 600–700 | 有明确内容分组时使用 |
| 控件及账目主文字 | 14px / 600–650 | 设置入口、账目分类、操作按钮 |
| 选定值、正文 | 14px / 500 | 语言/主题值、说明正文 |
| 辅助说明 | 12px / 500 | 帮助文字、次级摘要 |
| 紧凑元信息 | 11px / 500 | 账目时间、成员、条数；不承担关键操作 |
| 可编辑输入 | 16px / 500 | 表单输入及选择器，避免 iOS 聚焦自动放大 |

首页金额及数字键盘保留其独立的大数字层级。金额使用等宽数字，输入框不要再加装饰性的多层聚焦外框。不要将全部标题、选定值和说明统一加粗。

`src/type-system.css` 最后导入，管理这些角色；`journal-materials.css` 管纸面和插图材质；`secondary-motion.css` 管操作反馈。新增样式优先落在对应职责文件，避免继续增加互相覆盖的临时样式文件。

## 字体及语言

- 原有 Nunito 改为随应用发布的 `Pocket Nunito`，包含 Latin、Latin extended、Cyrillic、Cyrillic extended 四个按字符范围加载的子集。乌克兰语和格里夫纳符号有对应字形。
- 中文仍使用设备的 PingFang SC / Microsoft YaHei。不能声称不同操作系统的中文字形完全相同；三语都要实际检查换行。
- 字体源、SHA、OFL 许可保存在 `public/fonts/nunito/`。页面不再依赖 Google Fonts 的外部请求。
- 长选项允许利用剩余空间换行，主题名不得为了保留空白而过早省略。金额与币种作为一个整体保持不换行。

## 组件与实图

- 底色仍为四种现有主题：抹茶、芝士、白桃、海盐。图片共用温润奶白、灰绿、淡杏、浅蓝、浅黄，主题改变界面配色，不给每个图标再加一种高饱和底框。
- 一张图片承担一个语义。分类实图尺寸：主页 28px、编辑器 32px、账目列表 36px；它们对应同一套原图，不为不同页面重画互不相干的版本。
- 实图为装饰层，`alt=""`、`aria-hidden`、禁止指针事件。标签、金额、日期、数字、按钮语义都保留为真实 DOM。
- 分类素材映射由 `category-art.mjs` 管理：只有预设 ID、原始图标及原色均匹配时使用实图。用户自选图标、颜色和历史账目快照保持原样；图片下载失败回退到原图标。
- 小箭头、关闭、删除等精确操作符号继续用清楚的线条；不能为了填满素材数，把容易识别的操作变成复杂插画。
- 页背景和卡片复用纸面纹理。大插图只用于空状态或明确主视觉；已经有金额、头像、分类的行不再塞入第二张装饰图。
- PNG 原件及生成记录归档，运行界面仅加载 WebP。新增图片必须先用小尺寸实看，不能仅检查大图。

## 间距与操作

- 首页分类单行 40–48px；主页必须保持一个手机视口。插图不得拉高分类条或挤压键盘。
- 设置行最小 54px，标签与选定值间距 12px；选定主题整块可点，不限于右侧小箭头。
- 表单有真实标签，长名称可换行；抽屉保存与关闭命中区至少 44px。布局不得依赖中文短字符串碰巧能放下。
- 底部导航固定，内容预留安全区。全页截图中的固定导航位于视口位置，不据此认定页面底部布局；必须滚动到控件并实点检查。
- 装饰随所属组件运动，不给每张素材独立循环弹跳。常用操作只动画 transform/opacity；命中框静止，内部内容按压和回弹。
- 共享抽屉保持 160ms 有限退出，备注现金飞行保持独立时序，不叠加延迟。连续操作从当前绘制帧接手。
- 不恢复用户已经取消的全局减少动态门控。不要用桌面截图或自动化功能通过冒充 60/120Hz 实机帧率证明。

## 验收

分类和字体组合验证见 `tests/category-materials.browser.cjs`；四主题三语的页面/弹窗矩阵见 `tests/material-system.browser.cjs`。键盘、备注、分类滚动与表情窗口分别沿用原回归。所有 Vite 浏览器套件按顺序执行，避免共享缓存竞争。
